## 2. Rust → Swift (FFI) の効率性

### ✅ 良好な点

1. **FFIインターフェース**
   - `rust_process_key` が JSON 文字列を返す設計
   - メモリ管理（`rust_free_string`）が実装されている

2. **Panic処理**
   - `catch_unwind` による Rust panic の捕捉が実装されている

### ✅ 修正完了（2024年11月）

1. **戻り値型の不一致** ✅ **修正済み**
   - **修正前**: Rust側 `u8`、Swift側 `UnsafePointer<CChar>?` の不一致
   - **修正後**: 両方とも `*mut c_char` / `UnsafeMutablePointer<CChar>?` に統一
   - **実装**: null = 成功、非null = エラーメッセージのC文字列を返す
   - **ファイル**: `rust_core/src/ffi.rs`, `mobile/iOS/CyrillicKeyboard/Engine/RustCoreFFI.swift`

2. **エラーハンドリング** ✅ **改善済み**
   - 詳細なエラーメッセージを返すように実装
   - UTF-8エラー、パニック、初期化エラーなどに対応
   - Swift側でエラーメッセージを適切に解放するように修正

## 3. Rust → Kotlin (JNI) の効率性

### ✅ 良好な点

1. **JNIインターフェース**
   - 型の一貫性が保たれている
   - `jboolean` (JNI_TRUE/JNI_FALSE) で成功/失敗を返す ✅
   - `jstring` でJSON文字列を返す ✅

2. **メモリ管理**
   - JNIの `new_string` を使用しており、GCが管理する ✅
   - Rust側で適切に `into_raw()` を使用 ✅

3. **Kotlin側のラッパー**
   - `RustCoreEngine` クラスで型安全なラッパーを提供
   - JSONデシリアライゼーションが実装されている

### ✅ 現在の実装状況

1. **JSONシリアライゼーション**
   - 現在: `serde_json::to_string` と `JSONDecoder` を使用
   - **評価**: ナノ秒単位のオーバーヘッドで、要件（<16ms）を満たしている
   - **現状**: パフォーマンス問題なし。必要に応じて最適化可能

2. **スキーマのロード戦略**
   - 現在: 遅延ロード（プロファイル切替時にロード）
   - **評価**: メモリ効率が良く、要件を満たしている
   - **現状**: 実装は適切。メモリ使用量とレイテンシのバランスが取れている
