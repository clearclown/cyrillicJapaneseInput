# Pismo - キリル文字日本語IME 要件定義書

**バージョン**: 1.0.0
**作成日**: 2025-11-22
**ステータス**: 確定版

---

## 1. プロジェクト概要

### 1.1 目的

キリル文字配列を使用して日本語（平仮名・漢字）を入力できるIME（Input Method Editor）を開発する。

### 1.2 基本コンセプト

**「日本語ローマ字入力のローマ字部分をキリル文字に置き換える」**

#### 入力フロー
```
キリル文字入力 → 音韻キー → 平仮名 → 漢字変換
К + А → "ka" → "か" → "家" / "可愛い" 等
```

### 1.3 対象ユーザー

- キリル文字圏（ロシア、セルビア、ウクライナ等）の日本語学習者
- 日本語話者でキリル文字を学習したい人
- 多言語環境での日本語入力を必要とする人

## 2. 機能要件

### 2.1 サポート言語プロファイル

以下の全ての言語プロファイルを実装する（`docs/cyrillicJapaneseInput.xlsx`に基づく）：

#### 2.1.1 ロシア語（標準）
- **ID**: `rus_standard`
- **キーボード配列**: ЙЦУКЕН (JCUKEN)
- **特徴**:
  - 母音: А, И, У, Э, О
  - 拗音用: Я, Ю, Ё
  - 例: КА → か, КЯ → きゃ

#### 2.1.2 セルビア語
- **ID**: `srb_cyrillic`
- **キーボード配列**: ЉЊЕРТ (QWERTZ-based Cyrillic)
- **特徴**:
  - 特殊リガチャ: Њ (nya), Љ (rya/lya), Ђ (ja), Џ (ja/ju)
  - 特殊子音: Ћ (chi)
  - 例: КА → か, КЈА → きゃ, Ћ → ち

#### 2.1.3 ウクライナ語
- **ID**: `ukr_cyrillic`
- **キーボード配列**: ЙЦУКЕН (Ukrainian variant)
- **特徴**:
  - 固有文字: І (i), Ї (yi), Є (ye), Ґ (g)
  - 例: КА → か, КІ → き

#### 2.1.4 ブルガリア語
- **ID**: `bul_bds`
- **キーボード配列**: БДС (BDS 5237:2006)
- **特徴**:
  - 母音と子音が左右に分離
  - 固有文字: Ъ (yer)
  - 例: КА → か, КЪ → く

#### 2.1.5 ロシア語（分析モード）
- **ID**: `rus_analytical`
- **キーボード配列**: ЙЦУКЕН (JCUKEN)
- **特徴**:
  - 音韻構造を明示的に表現
  - 拗音: Кьа (kya), Кью (kyu) - 軟音符使用
  - 撥音: Нъа (n'a) - 硬音符使用
  - デバッグ・学習用途

### 2.2 入力方式

#### 2.2.1 基本入力（2キー方式）

**清音（50音）**:
```
子音 + 母音 → 平仮名
К + А → か
С + И → し
Т + У → つ
```

**濁音・半濁音**:
```
Г + А → が
Б + А → ば
П + А → ぱ
```

**拗音**:
```
К + Я → きゃ
С + Ю → しゅ
Ч + О → ちょ
```

#### 2.2.2 単独キー入力

**撥音**:
```
Н (単独) → ん
```

**母音**:
```
А (単独) → あ
И (単独) → い
У (単独) → う
Э (単独) → え
О (単独) → お
```

#### 2.2.3 特殊入力

**促音（っ）**:
```
子音を2回連続入力
КК → っk (次の子音を待つ)
ККА → っか
```

**長音（ー）**:
```
母音を2回連続入力
トーキョー: Т + О + О + К + Я + О + О
```

**音節分離**:
```
んあ: Н + ' + А (アポストロフィで分離)
または: Н + Ъ + А (硬音符で分離)
```

### 2.3 漢字変換

#### 2.3.1 変換エンジン

**Phase 1**: Mock辞書（130+語）
- 基本的な名詞、動詞、形容詞
- 学習機能付き

**Phase 2以降**: 本格的な変換エンジン統合
- azooKey KanaKanjiConverter
- または独自エンジン

#### 2.3.2 変換モード

**手動変換**:
- Space キー押下で変換開始
- 候補一覧表示
- 数字キー(1-9)で候補選択

**ライブ変換** (オプション):
- 入力中に自動変換
- 文節分割
- リアルタイム候補表示

#### 2.3.3 候補表示

**候補バー**:
- 横スクロール可能
- 左右スワイプでナビゲーション
- タップで選択
- 数字インジケーター (①②③)

### 2.4 プロファイル管理

#### 2.4.1 プロファイル切り替え

- 設定アプリから選択
- キーボード上でリアルタイム切り替え
- 前回使用したプロファイルを記憶

#### 2.4.2 プロファイル設定

各プロファイルの設定:
- キーボードレイアウト定義
- 変換スキーマ (JSON)
- 表示名（日本語・英語）

## 3. 非機能要件

### 3.1 パフォーマンス

| 項目 | 要件 | 測定方法 |
|------|------|----------|
| 入力遅延 | < 10ms | キー押下から文字表示まで |
| 変換速度 | < 50ms | Space押下から候補表示まで |
| メモリ使用量 | < 50MB | キーボード拡張の常駐メモリ |
| バッテリー消費 | 標準IMEと同等 | 1時間連続入力での比較 |

### 3.2 デザイン

**最優先要件**: **iOS標準キーボードに完全準拠**

#### 3.2.1 外観
- iOS標準キーボードと同一のビジュアルデザイン
- システムカラーに対応（ライト/ダークモード）
- キー形状、サイズ、間隔を標準に合わせる

#### 3.2.2 アニメーション
- キープレス時のスケールアニメーション
- 候補表示時のフェードイン
- モード切り替え時のトランジション

#### 3.2.3 ハプティックフィードバック
- キー押下時の触覚フィードバック
- 変換確定時のフィードバック
- エラー時の警告振動

### 3.3 ユーザビリティ

#### 3.3.1 学習曲線
- 初回起動時のチュートリアル
- ヒントラベル表示（各キーに対応平仮名を表示）
- 入力例の表示

#### 3.3.2 エラーハンドリング
- 無効な組み合わせの入力時のフィードバック
- バッファ状態の視覚化（アンダーライン表示）
- エラー音・振動による通知

#### 3.3.3 アクセシビリティ
- VoiceOver対応
- 大きい文字サイズ対応
- コントラスト調整

### 3.4 品質

**最優先要件**: **テストカバレッジ重視**

#### 3.4.1 テスト目標
- ユニットテスト: 80%以上のカバレッジ
- UIテスト: 主要フロー100%カバー
- 統合テスト: 全プロファイル × 全入力パターン

#### 3.4.2 テスト種別
1. **変換ロジックテスト**: 全スキーマ × 全パターン
2. **UIインタラクションテスト**: タップ、スワイプ、長押し
3. **パフォーマンステスト**: 応答時間、メモリ使用量
4. **回帰テスト**: 既存機能の動作保証

## 4. システムアーキテクチャ

### 4.1 プラットフォーム

#### 優先順位
1. **iOS** (16.0+)
2. **Android** (13+)

### 4.2 技術スタック

#### 4.2.1 iOS
- **言語**: Swift 5.9+
- **UI**: UIKit (キーボード拡張), SwiftUI (設定画面)
- **変換エンジン**: Rust Core (FFI)
- **フレームワーク**: Natural Language Framework

#### 4.2.2 Android
- **言語**: Kotlin
- **UI**: Jetpack Compose
- **変換エンジン**: Rust Core (JNI)

#### 4.2.3 共通
- **Core Engine**: Rust
- **データフォーマット**: JSON
- **ビルドツール**: XcodeGen (iOS), Gradle (Android)

### 4.3 データフロー

```
[ユーザー入力]
    ↓
[CyrillicKeyboardView] ← UIイベント
    ↓
[CyrillicInputManager] ← バッファ管理
    ↓
[RustCoreFFI] ← スキーマ検索
    ↓
[japaneseKanaEngine.json] ← 音韻 → 平仮名
    ↓
[KanjiConversionEngine] ← 平仮名 → 漢字
    ↓
[CandidateBarView] ← 候補表示
    ↓
[DisplayedTextManager] ← テキスト挿入
    ↓
[UITextDocumentProxy] ← OS統合
```

## 6. 制約事項

### 6.1 技術的制約
- iOS Keyboard Extension のメモリ制限（約50MB）
- ネットワークアクセス不可（Full Access不使用の場合）
- バックグラウンド実行制限

### 6.2 スコープ外
- カタカナモード（v1.0では非対応）
- 絵文字入力
- 音声入力
- 手書き入力
- クラウド同期
